Executive Summary & System Vision

Unifying Yield Analytics, PMS Operations, and CRM Activation via Google ADK

Target Problem

  • Data silos between BigQuery Data Warehouse, Resalys PMS, and CRM tools.
  • 24 to 48 hours lag from detecting an occupancy drop to launching a promotional flash campaign.
  • Manual coordination risk and potential unapproved stock modifications.

The Solution & Value Delivered

  • Supervisor Multi-Agent Pattern: Root orchestrator delegating to specialized child agents.
  • Cycle Time Reduction: From days to < 5 minutes for full yield recovery workflows.
  • Zero Data Duplication: Direct text-to-SQL on BigQuery.
  • HITL Security Gate: Strict interactive confirmation for all write operations.

Architectural Decisions & Invariants

Binding Constraints for Downstream Builders (AD-1 to AD-7)

AD-1 Topology

Supervisor Pattern

All client turns land at ECG_Supervisor_Agent. Sub-agents cannot be invoked directly.

AD-2 Governance

HITL Gate

Mutating calls (PUT, POST, DELETE) pause for explicit interactive user card approval.

AD-3 Security

Identity Passthrough

Cloud Identity bearer tokens forwarded verbatim to Apigee and BigQuery IAM.

AD-4 Analytics

Zero Data Duplication

Text-to-SQL executes live on BigQuery ecg_analytics without local caching.

AD-5 Integration

Apigee OpenAPI

PMS Operations agent binds strictly to Apigee REST OpenAPI specs.

AD-6 Marketing

Draft Staging

Assets saved to GCS; CRM webhooks stage draft campaigns only.

Security Model & Telemetry

Enterprise-grade IAM Passthrough, Audit Logs, and Latency SLAs

Security & Governance

  • OAuth2 Bearer Token Passthrough: User identity determines data and API visibility.
  • Least Privilege Enforcement: Zero service-account escalation.
  • Immutable Action Manifest: HITL cards show exact payload parameters before execution.

Observability & SLAs

  • Vertex AI Agent Observability: Distributed tracing across agent reasoning chains.
  • SQL Audit Trail: Every generated SQL query logged with user ID timestamping.
  • Performance Targets: Yield query < 3.5s; PMS update < 1.2s; E2E workflow < 5m.
